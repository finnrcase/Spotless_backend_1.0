# Data decisions

Version 1 jurisdiction is the official NavigateLA layer 414 City of Los Angeles polygon. LA County, Santa Monica, Beverly Hills and other municipalities are not silently included. Streets are intersected with this polygon; boundary fragments preserve source asset and object IDs. The Westwood/UCLA pilot is an explicit configurable bounding box (-118.465,34.045,-118.425,34.080), not a claim about official neighborhood boundaries. Campus/private roads remain subject to jurisdiction/parking review.

The official current BOE centerline layer 341 supplies source segments. A `segment_id` contains dataset namespace, asset ID, object ID and sorted clipped-part index. WKB hashes capture geometry version. A source republish can renumber object IDs; split/merge lineage across republications needs explicit reviewed mappings, not a claim of permanent vendor IDs. Canonical endpoint order fixes left/right regardless of source digitization direction. Source attributes remain in staged snapshots. These are source street segments; complex intersections, divided roads and un-noded crossings need topology review before treating every object as exactly one navigable block.

Each segment has left and right faces. Default geometry is a labelled **approximate 8 m centerline offset**, not surveyed curb width. Physical authoritative curb footprints are preferred only when they lie within 5 m of that approximation and cover at least 80% of it within a 1 m tolerance. Those polygons describe physical footprints, not legal parking extents; both the method and source IDs are retained. Other curbs remain available as separate authoritative geometry. This provisional association needs survey validation; it does not turn footprint area into capacity.

The street service joins planning rows: `AutoID` is unique per API row, while BOE `OBJECTID`/`ASSETID` can repeat. Identical physical geometry is collapsed while preserving every API row ID and designation. Distinct geometries under the same physical IDs receive a version-derived variant suffix. Invalid curb footprints are counted and excluded from authoritative association, without automatic geometry repair.

Freeway/ramp/walkway/paper-street source labels are excluded where present; remaining streets are `needs_review`, never assumed legally parkable. Width, intersection daylighting, hydrants, curb cuts, loading, bus stops, bike lanes, permits, sweeping and temporary rules must be reconciled before capacity is estimated. The current pipeline deliberately leaves capacity null. Measured marked-space counts and field surveys are preferable; a later exclusion-adjusted estimate must retain lower/upper bounds, vehicle-length assumptions and an exclusion completeness indicator.

Raw data is content-addressed and immutable; request cache pointers can refresh without replacing raw bytes. Every attempted download records URL, parameters, status, retrieval time, size and SHA-256. Resume operates at completed request/page/file boundaries; interrupted single files restart, rather than pretending to support HTTP byte-range continuation. Serial requests, 429/5xx retries and backoff limit pressure. Bounded raw responses cannot silently become partial datasets. ArcGIS IDs and SODA counts are checked. SODA count/order checks cannot detect every concurrent update: this is disclosed, especially for live occupancy.

Parquet/GeoParquet are local interchange artifacts. DuckDB views query them without a server; WGS84 geometry is stored with CRS metadata, and distance calculations use NAD83 UTM 11N metres. Raw source timestamp text survives. Canonical timestamps are timezone-aware UTC; recurring rules use America/Los_Angeles and effective date intervals [from,to). Intended parking must satisfy every overlapping restriction throughout [arrival,arrival+duration), including midnight, DST and permit class. The contracts support that requirement; no legal-rule engine is claimed complete.

`schemas/` JSON Schema files are interchange contracts exported from Pydantic models. Spatial tables also carry GeoParquet metadata; field provenance and source manifests distinguish observed/derived/assumed/imputed/unavailable values. Current wide analytical tables are convenient projections, not lossless instances of every interchange contract. Intake validates manual records; normalization validates observed state/time. Publish adapters must populate complete per-field provenance and effective dates before application use.

Static features need vintage/validity; dynamic features need observation/issue and availability times. Forecast-weather training must use the forecast issued before the decision, not realized weather as if it were known. Event cancellations and academic calendars need revisions. Citations, payments, business accounts and service requests remain biased contextual features, never direct occupancy labels.

Move to PostGIS when simultaneous application writes, indexed radius/route queries, multiuser surveys or incremental spatial updates justify a service. Preserve IDs, WGS84 geometries (GiST indexes), UTC timestamptz, effective tstzrange intervals and lineage tables. Use migration scripts and EXCLUDE constraints for overlapping inventory versions, with object storage retained for raw snapshots. No database hosting or deployment has been provisioned.
